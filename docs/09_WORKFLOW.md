# قواعد سير العمل

- كل دور هيتقسّم لتعديلات صغيرة متتالية (نفس منطق "3 تعديلات × 5 طلبات" اللي كان
  متبع في Lovable)، لكن بما إننا دلوقتي في Claude Code مباشرة: **كل تعديل = مهمة
  هندسية محددة واحدة** تُنفَّذ، يتشغّل `bun run dev` للتأكد، يتعمل commit بوصف
  واضح، وبعدين ننتقل للي بعده. مفيش داعي لصيغة "برومت" — الوصف المباشر للمهمة
  كافي.
- **Commit صغير ومتكرر** بوصف واضح بالعربي أو الإنجليزي (مش commit ضخم يجمع كذا
  حاجة).
- عند الشك في نمط تصميم (زي إزاي تتعامل مع state مشترك)، **ارجع لنمط `auth.ts`**
  الموجود بالفعل كمرجع — هو النمط المُعتمد في هذا المشروع، لا تخترع نمط تاني
  بجانبه.
- ملف `AGENTS.md` الأصلي فيه ملاحظة خاصة بمزامنة Lovable (git history) — Lovable
  لم يعد مصدر التعديل الأساسي، لكن اتركه كما هو احتياطياً ما لم يُطلب حذفه.
